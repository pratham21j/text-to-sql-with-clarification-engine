# Project: Text-to-SQL with Clarification Engine

## Objective

Build a functional Windows desktop application for a B.Tech minor project.

The application must convert natural-language questions into SQL, detect material ambiguity, ask clarification questions when necessary, preserve conversation context, validate SQL, execute safe read-only queries, and display results.

This is a minor project. Prioritize a working, testable application over production infrastructure.

## Technology Stack

- Python
- CustomTkinter for the desktop interface
- SQLite for the demonstration database
- Google Gemini API using the official google-genai SDK
- SQLGlot for SQL parsing and validation
- pytest for automated testing
- python-dotenv for local configuration
- Git for version control
- PyInstaller for optional executable packaging

## Database

Create a synthetic academic database with:

- students
- departments
- courses
- enrollments
- examinations

Generate deterministic sample data.

Do not use real student records or confidential information.

Implement database schema retrieval programmatically.

## Clarification Engine

The system must distinguish between clear, ambiguous, and incomplete questions.

Example clear question:
"Show all CSE students."

Example ambiguous question:
"Show the best students."

Possible clarification:
"Should students be ranked by CGPA, marks, or attendance?"

The system must preserve the original question, store clarification responses, resolve user intent, and generate SQL using the resolved intent.

Do not rely exclusively on keyword matching.

Avoid unnecessary clarification questions.

## Gemini Integration

Use the official google-genai Python SDK.

Read GEMINI_API_KEY and GEMINI_MODEL from environment variables.

Keep all LLM integration in a dedicated provider module.

Never hardcode credentials.

Do not switch to paid services or enable billing without explicit approval.

Handle API failures and quota exhaustion gracefully.

Use mocked model responses for automated tests wherever possible.

## SQL Safety

- Allow only supported read-only queries.
- Parse SQL before execution.
- Reject destructive and data-modifying statements.
- Reject unsupported multiple statements.
- Validate referenced tables and columns.
- Apply a configurable result limit.
- Handle database errors safely.
- Never execute arbitrary code generated by the LLM.
- Never bypass validation to make a test pass.

## Desktop Interface

Use CustomTkinter.

Provide:

- A question input field.
- A conversation display.
- A clarification interface.
- SQL preview.
- Tabular query results.
- Loading indicators and useful error messages.

Do not build a website or require a browser to use the application.

## Definition of Done

The application must:

1. Launch as a desktop application.
2. Accept natural-language questions.
3. Retrieve the relevant schema.
4. Generate SQL for clear questions.
5. Ask meaningful clarification questions for ambiguous requests.
6. Incorporate clarification responses correctly.
7. Validate SQL before execution.
8. Reject unsafe queries.
9. Display results and generated SQL.
10. Pass its automated tests.
11. Include reproducible setup instructions.
12. Document known limitations.
